Déploiement de cp|WIRE sur un serveur interne

Cockpit de pilotage chef de projet · connecté à Jira (armonie.atlassian.net)

1En deux mots

cp|WIRE est une petite application web de pilotage de portefeuille de tickets Jira (vue consolidée, comptes-rendus, brief matinal). Techniquement : un serveur Node.js (Express) qui sert aussi l'interface React pré-construite — un seul conteneur Docker, sans base de données externe. Il interroge l'API Jira Cloud en lecture, et écrit (commentaires / changement de statut) uniquement à la demande de l'utilisateur.

2Prérequis

  • Un hôte capable d'exécuter Docker (recommandé) ou à défaut Node.js 20+.
  • Ressources modestes : 1 vCPU, 512 Mo–1 Go de RAM, ~200 Mo de disque.
  • Accès réseau sortant en HTTPS vers armonie.atlassian.net (et, optionnellement, vers les API d'IA si la fonction est activée).
  • Le service écoute sur le port 4000 (à placer derrière le reverse-proxy interne).
  • Sonde de santé disponible sur /api/health.

4Persistance (important)

L'application conserve, dans le dossier /app/data du conteneur, une « photo » des tickets (pour des actualisations rapides et incrémentales) ainsi que les fiches dossiers. Il faut monter un volume persistant sur /app/data pour que ces données survivent aux redémarrages et mises à jour.

5Déploiement Docker

# Construction de l'image (depuis le dossier du projet)
docker build -t cpwire:latest .

# Lancement avec volume persistant + variables d'environnement
docker run -d --name cpwire --restart unless-stopped \
  -p 4000:4000 \
  -v /srv/cpwire/data:/app/data \
  -e JIRA_BASE_URL="https://armonie.atlassian.net" \
  -e JIRA_EMAIL="compte-service@armonie.group" \
  -e JIRA_API_TOKEN="•••" \
  -e AUTH_EMAIL="•••" \
  -e AUTH_PASSWORD="•••" \
  -e PROJECTS="TEDL,PEM,TDSS,PDFP,TMT,PTAF,TBEL,TBAL,PBAL,TIMA,PIMA,PIMA2,TDIA" \
  -e ME="Nicolas Durand" \
  -e TARGET_DONE="Terminé" \
  cpwire:latest

Les variables peuvent aussi être placées dans un fichier .env (--env-file) ou gérées via docker compose / l'orchestrateur interne.

6Exposition

Publier le port 4000 derrière le reverse-proxy interne (Nginx / Traefik / IIS…) avec un nom de domaine interne et un certificat HTTPS. L'accès peut être restreint au réseau de l'entreprise ou au VPN. L'application gère sa propre authentification (identifiant + mot de passe ci-dessus) ; un SSO peut être ajouté en amont au niveau du proxy si souhaité.

7Mise à jour

# Reconstruire l'image avec la nouvelle version, puis relancer
docker build -t cpwire:latest .
docker stop cpwire && docker rm cpwire
docker run -d --name cpwire ... (mêmes options qu'à l'étape 5)

Le volume /app/data étant externe au conteneur, les données (cache, fiches) sont conservées d'une version à l'autre.

8Sécurité & données

  • Le jeton Jira reste sur l'infrastructure d'Armonie ; il convient d'utiliser un compte de service dédié avec les seuls droits nécessaires sur les projets listés.
  • Aucune donnée n'est stockée hors du volume /app/data ; aucune base externe n'est requise.
  • Les fonctions d'IA et de messagerie sont désactivées par défaut et ne s'activent qu'en renseignant les variables optionnelles correspondantes.
